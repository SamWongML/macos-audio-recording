# Audio editor anatomy: how peers fill the space around a waveform

**Research question (issue #71):** AppTape's detail pane is one greedy waveform lane stretched over the full window height, one transport row, and nothing else — no ruler, no timecode, no meters, no region chrome. How do modern audio editors — peer trim-and-export tools especially — fill that space?

**AppTape's current baseline**, for comparison throughout: the editor (`EditorView.swift`) is a `NavigationSplitView` — Library sidebar (one Recording per row, ~32pt tall, source name, time, and a masked-off background waveform silhouette that fades at the edges) → detail pane → a permanently visible Export inspector. The detail pane (`TrimTimeline.swift`) is one waveform lane that always fits the full window width (no zoom), drawn as a shape with a lighter "peak" overlay and a solid "body" tint fill; trimmed-away regions are dimmed via a translucent overlay rather than cropped away (Trim never deletes anything); two capsule drag handles with chevron glyphs; a thin playhead line with a dot; hatched bands for Seams; an optional ±2s "loupe" magnifier while dragging a handle. Below that: a single transport row with one play/pause glass button, a monospaced display-only position readout, a trailing "Trim h:mm:ss–h:mm:ss" or "Whole Recording · duration" label, and a "Reset" link when trimmed. A ruler component exists in code but is always passed `showsRuler: false`, so it never renders. There are no level meters in the editor. The window toolbar is deliberately bare — only the system sidebar toggle. The empty state is a plain `ContentUnavailableView("No Recording selected", systemImage: "waveform")`.

Sourcing note: every claim below is cited inline. Vendor documentation and product pages were fetched directly; where a vendor page could not be retrieved despite repeated attempts (noted explicitly per app), a secondary source is used and flagged as such. Screenshot-only findings are phrased as "per screenshot/alt text at `<URL>`" and describe only what the source states or an image's own caption/alt text says, not inferred behavior.

## Fission (Rogue Amoeba)

Fission is the closest single analogue to AppTape: a dedicated trim/crop/split editor, not a DAW.

1. **Waveform drawing:** Fission's changelog confirms the waveform is drawn around a centerline — version 2.9.5 (Aug 13, 2026) restored a regression: "The zero dB center line has been restored to Fission's waveforms" (rogueamoeba.com/fission/releasenotes.php). This confirms a mirrored, centerline-referenced waveform. The manual does not state fill-vs-outline or per-channel/stereo lane details explicitly (rogueamoeba.com/support/manuals/fission/?print=true).
2. **Time ruler:** Yes — an "upper timeline ruler" exists above the waveform; it regressed and was fixed in v2.8.7 (Aug 13, 2024): "The upper timeline ruler, which went missing in Fission 2.8.6, has been found and restored" (rogueamoeba.com/fission/releasenotes.php). Separately, v2.9.0 (Sep 10, 2025) added an overview strip: "the overview bar at the top of a file now more clearly shows the visible area when zoomed in" (rogueamoeba.com/fission/releasenotes.php) — confirming Fission supports zoom, with a minimap-style overview bar showing the zoomed viewport, something AppTape's timeline (fixed to full width, no zoom) does not have.
3. **Timecode:** Not documented as a typable field in the reachable manual pages; the manual describes a "playhead" and marking start/end points by dragging or by keyboard shortcut, not a numeric entry field (rogueamoeba.com/support/manuals/fission/?print=true).
4. **Transport controls:** Keyboard-driven: Space toggles play/pause, Cmd-L loops playback, Shift-Cmd-D previews the start of a selection, Shift-Cmd-E previews the end (rogueamoeba.com/support/manuals/fission/?print=true). Toolbar-level editing actions include Remove, Crop, Split, Fade In, Fade Out, and Normalize buttons (rogueamoeba.com/support/manuals/fission/?print=true).
5. **Trimmed-away region:** Not explicitly documented in the fetched manual/release-note text (Fission's core operations are Crop and Remove, which are literally destructive/subtractive edits to the working buffer, unlike AppTape's non-destructive Trim — the manual states selection is made "by dragging either edge" and adjusted from there) (rogueamoeba.com/support/manuals/fission/?print=true).
6. **Level meters:** Not found in the reachable manual/product/release-note pages after search and fetch attempts on rogueamoeba.com/fission/, rogueamoeba.com/support/manuals/fission/ (both the welcome and Basics pages), and the release notes — flagged as not documented, not confirmed absent.
7. **Window toolbar:** The editing window has an Inspector that can be shown on the right side, with ID3 tags/lyrics/artwork editing and a Summary tab showing bitrate, sample rate, etc. (rogueamoeba.com/support/manuals/fission/?page=basics, alt text of the embedded screenshot: "Fission's Editing Window", image file `images/edit.png`, per that same fetched page). A separate Batch Converter view handles format conversion (same source).
8. **Empty state:** Not documented in the reachable manual pages.
9. **Sidebar/file-list row:** Fission edits one file at a time in its editing window rather than presenting a persistent multi-file sidebar list in the base manual pages reached; not documented.
10. **Color/theme note:** Fission 2.9 (Sep 2025) reworked its visual language: "the entire application has been given a virtual fresh coat of paint," with updates to "the Start window, the editing window, and the Batch Converter," and "the light theme has been refreshed to lean into the app's gold coloring" (weblog.rogueamoeba.com/2025/09/10/fission-2-9-gets-a-fresh-face/).

## Audio Hijack (Rogue Amoeba)

Audio Hijack is a capture/routing tool, not an editor — included per the issue brief as a Rogue Amoeba peer, useful mainly for how it handles meters and session/file lists rather than trim UI.

1. **Waveform drawing:** No waveform display was found in the reachable manual pages for the Session window or the Recordings list; the interface centers on a block-based signal-flow diagram, not a waveform (rogueamoeba.com/support/manuals/audiohijack/?print=true).
2/3. **Ruler / timecode:** Not applicable — there is no waveform-timeline view in the documented UI; navigation is session/recording-based rather than timeline-based.
4. **Transport controls:** The primary control is coarse: "Once a session is configured, click the Run button to begin capturing audio. Click Stop to toggle the session back off" (rogueamoeba.com/support/manuals/audiohijack/?print=true). The Recorder block adds "Pause Recording" and "Split File" buttons, both on the block face and in its popover (same source).
5. **Trimmed-away region:** Not applicable; Audio Hijack does not trim, it records and splits live capture.
6. **Level meters:** Central to the design. "Meter blocks provide visual meters so you can see how audio is flowing" — these are optional blocks users drop into the audio-routing grid, not a fixed part of one lane (rogueamoeba.com/support/manuals/audiohijack/?print=true). At the session-list level (not per-recording), the Session List table has a dedicated, resizable **Meters column**: "the Meters column can be resized between 5 and 30 bars wide" (weblog.rogueamoeba.com/2023/01/20/level-up-to-audio-hijack-4-1/), and "Session meters are also now tied to the window width, and will disappear at the narrowest widths" (same source) — i.e., live per-session level bars live in a list row, not in a waveform pane.
7. **Window toolbar / chrome:** The main audio-routing canvas is called the "audio grid": "The audio grid is the heart of each session... you'll chain together blocks in the audio grid, creating a pipeline for audio to flow through," with "audio... shown in orange as it flows through the audio pipeline" (rogueamoeba.com/support/manuals/audiohijack/?print=true). A right-hand sidebar in each session window has five tabs: Blocks, Recordings, Schedule, Scripting, and Info (same source). The Session List window (separate from a session's own window) was redesigned in v4.1 to look "more like a standard Finder window in List view," with a "view options button" to toggle which of up to eight columns are shown, reorderable/resizable columns, and a contextual (Control-click) menu (weblog.rogueamoeba.com/2023/01/20/level-up-to-audio-hijack-4-1/).
8. **Empty state:** Not documented in the reachable pages.
9. **Sidebar/list row:** A session row in the Session List can show, per user configuration, the session name plus optional Recordings-count, Timers-count, and Meters columns — explicitly not a fixed one-line layout but a customizable table (weblog.rogueamoeba.com/2023/01/20/level-up-to-audio-hijack-4-1/). The in-session Recordings tab is "a list of recordings previously created by a particular session, as well as any in-progress recordings," where each item has a Play button and an Actions menu to reveal it in the Finder (rogueamoeba.com/support/manuals/audiohijack/?print=true) — no waveform thumbnail is documented for these rows.

## Piezo (Rogue Amoeba)

Piezo is Rogue Amoeba's "charmingly simple" one-button recorder — useful here as the minimal end of their own product line, closer to a recorder than an editor.

1. **Waveform drawing:** None documented. The manual describes the main window purely in terms of meters and a source selector, with no waveform view mentioned (rogueamoeba.com/support/manuals/piezo/?print=true).
2/3. **Ruler / timecode:** Not present — no ruler or numeric position field is documented; Piezo has no editing/scrubbing view at all.
4. **Transport controls:** A single Record button is effectively the whole transport: "you'll see the Record button illuminate, along with the VU meters" when active, and clicking again stops the recording (rogueamoeba.com/support/manuals/piezo/?print=true).
5. **Trimmed-away region:** Not applicable — Piezo has no trim/edit function documented.
6. **Level meters:** Front and center. "VU meters at the top show audio activity: when the needles move, audio is being received from the selected source," and "the decibel scale on the meters is calibrated and accurate" (rogueamoeba.com/support/manuals/piezo/?print=true) — needle-style VU meters, not a waveform, are the primary visual feedback.
7. **Window toolbar:** Below the meters sits "the Source selector, used to choose the application or device from which to record audio" (same source); a magnifying-glass icon reveals the finished file in the Finder (same source); clicking the file name or a settings button opens a popover to "choose your recording quality, name your clip, and add comments" (rogueamoeba.com/piezo/).
8. **Empty state:** Not documented; the whole window essentially *is* the empty/ready state until recording starts.
9. **Sidebar/file-list row:** Not documented — the manual describes no persistent list of past recordings inside the app itself. This is the strongest confirmation among the researched apps that "no waveform, no timeline" is a legitimate, shipped design for a single-purpose one-recording-at-a-time tool, though Piezo is a recorder, not a trim/export tool like AppTape.

## Descript

1. **Waveform drawing:** Descript exposes four selectable waveform *styles* for its animated/decorative waveform element: "Lines, Circle, Ring, or Wave" (help.descript.com/hc/en-us/articles/10256425252749-Waveforms). A **Mirror** option applies only to "Line and Wave" styles and "centers the waveform and adds a mirrored reflection below" — confirming Descript supports both single-sided and mirrored rendering as a toggle (same source). For Circle/Ring styles, a "Fill" setting sets waveform color (same source); the source doesn't specify solid-vs-gradient fill mechanics. The source doesn't document per-channel/stereo lane rendering. Note: this "Waveforms" feature governs a decorative, audio-reactive waveform graphic (an on-canvas visual element), distinct from the plain amplitude waveform drawn in the Timeline for editing.
2. **Time ruler:** Yes, in the Timeline. "The time ruler: Displays timecode, markers, comments, and audio levels" (help.descript.com/hc/en-us/articles/10249275208717-Timeline-overview-classic). The Timeline itself "is a more traditional view with audio waveforms" used to "trim, split, and move clips to adjust timing across your script and media layers" (help.descript.com/hc/en-us/articles/37585546799757-The-editor-interface). Zoom exists via "Fit scene" and "Fit composition" controls (help.descript.com/hc/en-us/articles/10249275208717-Timeline-overview-classic).
3. **Timecode:** The ruler is documented as a *display* ("Displays timecode, markers, comments, and audio levels" — help.descript.com/hc/en-us/articles/10249275208717-Timeline-overview-classic); no fetched source describes a typable/editable timecode entry field, so this is treated as display-only pending further evidence.
4. **Transport controls:** "The transport is the main playback and navigation control center, located at the top of the Timeline" (help.descript.com/hc/en-us/articles/10164534109837-Playback-and-navigation). Playback speed is adjustable up to 3x, and explicitly "only adjusts playback within the Descript editor" — it doesn't affect exports (same source). Frame-accurate stepping is supported: "Press the left or right arrow keys to step through your project one frame at a time" (same source). The playhead itself is color-coded and dual-rendered: "a blue cursor in the Script editor and a vertical blue line in the Timeline," and during playback "highlights the current word in your script" (same source) — tying playback position to the transcript, not just the waveform.
5. **Trimmed-away region:** Not explicitly documented in the fetched pages beyond "trim, split, and move clips" language (help.descript.com/hc/en-us/articles/37585546799757-The-editor-interface); Descript's script-based edit model (deleting words deletes the underlying media) makes "trim" closer to AppTape's Export than its non-destructive Trim.
6. **Level meters:** The ruler doc mentions "audio levels" as one of the things the time ruler displays (help.descript.com/hc/en-us/articles/10249275208717-Timeline-overview-classic), implying a levels overlay integrated into the ruler strip itself rather than a separate meter widget — but the fetched text doesn't elaborate on its visual form.
7. **Window toolbar / chrome:** The editor is organized into four named regions: "Script editor" (transcript-based text editing), "Scene editor" (visual preview/layout), "Timeline" (waveform-based trim/timing), and "Sidebar" panels (help.descript.com/hc/en-us/articles/37585546799757-The-editor-interface). The Sidebar hosts toggleable panels — Project, Media, Properties, and Comments per the View menu documentation (help.descript.com/hc/en-us/articles/37508206076429-Manage-the-editor-layout-with-the-View-menu). Notably, **the Timeline is hidden by default**: "the timeline is fully collapsed with no wordbar, visuals, or layer previews visible" when a project opens, revealed via a resize handle above the transport or Control+Option+T (help.descript.com/hc/en-us/articles/10249275208717-Timeline-overview-classic) — i.e. Descript's default view is script-first, not waveform-first, the opposite of AppTape's waveform-only layout.
8. **Empty state:** Not documented in the fetched pages.
9. **Sidebar/file-list row:** Not documented in the fetched pages beyond the existence of a "Project" panel among the toggleable sidebar panels (help.descript.com/hc/en-us/articles/37508206076429-Manage-the-editor-layout-with-the-View-menu).

## Sound Studio (Felt Tip)

Sound Studio is a straightforward record/edit/export tool for one file at a time — one of the closest peers to AppTape's job, and the best-documented one found here via its own reference manual.

1. **Waveform drawing:** Two stacked panes, not one. "The box just below the buttons is the 'Overview' waveform view. It always shows the waveform of the entire file and is not the editing area" — it's a navigation minimap: "Clicking and dragging in the overview will move the box" that represents the visible window (felttip.com/ss/reference.html). "The editing area is below the overview and stretches almost to the bottom of the window. This is where you make your selection, edit the audio, put down markers, and do other editing tasks" (same source). Stereo/multi-track files show one lane per channel, independently selectable: "For stereo files or files with more than two tracks, hold down the Command key while clicking in the appropriate channel to select that channel" (same source).
2. **Time ruler:** Yes, atop *each* of the two waveform views: "The default ruler along the top of the each view has markings in minutes, seconds and fractions of a second" (felttip.com/ss/reference.html).
3. **Timecode:** Display-only inline, but reachable as a typed jump target via a separate command: "In the bottom middle of the window is a time readout for the current cue position" (felttip.com/ss/reference.html); the manual frames going to a specific time as a menu/dialog action (a "Go To" style command) rather than clicking into the readout itself, so it is treated as display-only with numeric-entry navigation available via a separate command, not an inline editable field.
4. **Transport controls:** Centered at the bottom of the window: "return to zero, rewind, fast forward, play, and record" plus loop playback (felttip.com/ss/reference.html).
5. **Trimmed-away region:** Not documented as a persistent "trim" concept — Sound Studio's edit model is selection-then-destructive-edit (cut/delete/crop the selection), not a non-destructive Trim like AppTape's; the manual's Overview/editing-area split exists for navigation and precision, not for depicting a trimmed-away zone.
6. **Level meters:** At the bottom of the window: "the input level meter and input gain slider control... the output level meter and output gain slider control" (felttip.com/ss/reference.html). A separate, dedicated metering window also exists: "The Input Levels is a normal window that shows the current levels at the sound input" (same source).
7. **Window toolbar:** Not detailed beyond "the buttons" referenced above the Overview pane in the manual excerpt fetched; specific toolbar-button enumeration wasn't reached.
8. **Empty state:** Not documented in the fetched manual excerpt.
9. **Sidebar/file-list row:** Sound Studio edits one open document/window at a time in the fetched material; no persistent multi-file sidebar/list row format was documented.
10. **Retina rendering note (secondary):** A KVR Audio news item about a Sound Studio update mentions "improved waveform display now in Retina resolution" in v4.8.4 (kvraudio.com/news/felt-tip-updates-sound-studio-mac-audio-editor-to-v4-8-4-35183) — flagged as secondary (a third-party changelog aggregator, not felttip.com itself).

10. **Stereo Utilities (adjacent, confirmed):** A dedicated "Stereo Utilities" toolset offers Balance, Swap channels, and Invert phase operations on a stereo document (man.dsd.net/amadeus/en/edit_stereo.htm) — direct per-channel manipulation as a first-class feature, beyond just per-channel *display*.

## Hindenburg (Hindenburg Systems)

Hindenburg Pro is pitched explicitly as spoken-word/journalism software that fuses a transcript view with a waveform, which the issue brief flags as adjacent to Descript's model.

1. **Waveform drawing:** Hindenburg's own product page states the tool "combines waveform editing and transcript-based workflows" (hindenburg.com/products/hindenburg-pro/), and that page's own screenshot is captioned (image alt text, per the fetched page) "A glimpse into the Hindenburg PRO audio editing workspace, built for journalists and audio storytellers" (hindenburg.com/products/hindenburg-pro/) — confirming transcript-plus-waveform is the headline layout, though the fetched page text doesn't itself describe fill/mirroring/per-channel details. A user-facing toggle exists for waveform detail level: "Only show the Peak Value in the waveforms" is listed as an option in the app's guide, implying a default mode that shows more than peak alone (hindenburg.com/academy/guides/guides-hindenburg-pro/). A specific claim that Hindenburg draws "rectified" waveforms (peaks as light tops, RMS as a dark middle, no below-the-line mirroring) appears in Hindenburg's own support knowledgebase, but that exact article (support.hindenburg.com/knowledgebase/articles/1958584) could not be retrieved after four separate fetch attempts (each failed with a socket error) — this claim is therefore **not included as a sourced fact** here, only flagged as an unconfirmed lead for follow-up.
2/3. **Ruler / timecode:** Hindenburg has a "Counter" that "Shows Playhead and Selection Time" (hindenburg.com/academy/guides/guides-hindenburg-pro/) — a combined position/selection-length readout, toggleable from the interface options ("Shows / Hides the Clock with current time" is listed as a separate, related toggle) (same source). No source confirms whether the Counter is typable/editable.
4. **Transport controls:** Documented set: Space "toggles Play & Stop"; separate rewind, forward, "Home," and "End" navigation; "Loop Selection"; and a rehearsal mode to "Listen to the end result of an edit before you do the actual editing" (hindenburg.com/academy/guides/guides-hindenburg-pro/). A toggleable "Transport menu" is a distinct, hideable UI region (same source).
5. **Trimmed-away region:** Not documented in the fetched guide; Hindenburg's edit model (per the guide) is track-and-region based — "Delete/clear" removes audio outright and "Duplicate" copies a region or selection (search-result summary of hindenburg.com/academy/guides/guides-hindenburg-pro/) — closer to a destructive multitrack editor than AppTape's reversible Trim.
6. **Level meters:** Rich and switchable: the guide lists five selectable meter types — "Digital QPPM," "BBC PPM," "Peak," "VU," and "EBU R128" (loudness) (hindenburg.com/academy/guides/guides-hindenburg-pro/) — a broadcast-oriented meter set, notably including a loudness standard (EBU R128), which is conceptually close to AppTape's own Loudness concept even though Hindenburg exposes it as a live meter rather than an export-time correction.
7. **Window toolbar / chrome:** Customizable: users can show/hide the Transport menu, the "Clock with current time," and a CPU & Disk Usage monitor (hindenburg.com/academy/guides/guides-hindenburg-pro/). Per-track controls include volume, panning, and effects (same source).
8. **Empty state:** Not documented in the reachable pages.
9. **Sidebar/file-list row:** Not documented in the reachable pages; Hindenburg is multitrack (has "tracks" with add/delete/rename per the search summary of the guide) rather than single-file-at-a-time, which is a structural difference from AppTape.

## QuickTime Player trim UI (Apple) — the low-chrome floor

1. **Waveform drawing:** For an audio file being trimmed, QuickTime shows a trimming bar rather than a labeled/ruled waveform pane per se; the fetched support pages describe the trim *handles* and the playhead, not waveform rendering style (support.apple.com/guide/quicktime-player/trim-a-movie-or-clip-qtpf2115f6fd/mac).
2. **Time ruler:** Not present as a separate labeled ruler; the trimming bar itself is the only horizontal time-scrubbing element documented.
3. **Timecode:** Both display-only and separately typable, depending on where you look. The always-visible controls are display/scrub-oriented. But there is a dedicated typable entry point: "To navigate to a specific time-coded frame, choose View > Time Display > Go To Timecode, then enter the timecode you want" (support.apple.com/en-ca/guide/quicktime-player/qtp6cee0761b/mac) — "enter the timecode you want" is the source's own phrasing for what is a typable numeric field, reached via a menu command rather than living inline in the transport row. Separately, "View > Time Display" lets a user choose how the readout is formatted (support.apple.com/en-ca/guide/quicktime-player/qtp6cee0761b/mac).
4. **Transport controls:** "QuickTime Player has onscreen playback controls that let you play, pause, fast-forward, or rewind your video or audio file" (support.apple.com/en-ca/guide/quicktime-player/qtp6cee0761b/mac). The same controls surface volume, an AirPlay/external-playback menu, picture-in-picture, sharing, and a "More Controls" overflow for playback-speed selection (same source). These controls are an overlay that can be dragged out of the way rather than a fixed, permanently-docked row (same source).
5. **Trimmed-away region:** Cropped visually by the handle positions, not dimmed: "Drag the yellow handles in the trimming bar," and "the area outside of the yellow handles is the area to be trimmed" (support.apple.com/guide/quicktime-player/trim-a-movie-or-clip-qtpf2115f6fd/mac). Precision is available on demand: "click and hold a handle to see individual frames of the clip" (same source). The interface then shows only a "Trim button and the Cancel button" to commit or discard (same source) — trimming in QuickTime is a modal, commit-or-cancel action on the file itself, unlike AppTape's always-live, non-destructive Trim state.
6. **Level meters:** Not documented — QuickTime Player's trim UI has no meters in any fetched source.
7. **Window toolbar:** Minimal by design; the fetched pages describe only the floating playback-control overlay, not a persistent top toolbar with buttons beyond what's built into that overlay (support.apple.com/en-ca/guide/quicktime-player/qtp6cee0761b/mac).
8. **Empty state:** QuickTime Player's own default behavior on launch is to present an Open dialog rather than an empty document window — this specific behavior is documented only via a secondary source (an Apple Support Community thread, not an official guide page): "You would get an empty window if there are no QuickTime documents in your iCloud space... you can just cancel the Open dialog box" (discussions.apple.com/thread/252418781 — flagged secondary/community, not an official Apple guide).
9. **Sidebar/file-list row:** Not applicable — QuickTime Player is a single-document-per-window player/trimmer with no library or sidebar.

## Logic Pro & Ableton Live — the DAW ceiling, for contrast

Included per the issue brief purely as a density contrast; both are multitrack DAWs, not single-Recording trim tools like AppTape.

**Logic Pro (Apple):** The Audio Track Editor "shows a close-up view of the audio waveform of the regions on an audio track in the Tracks area," where users can "move and trim audio regions, split and join them," with "edits... non-destructive, so you can always return to your original recordings" (support.apple.com/guide/logicpro/overview-lgcp650a7dcc/mac). A third-party mirror of Apple's own Logic Pro Help — used here because Apple's official page returned only navigation chrome, not article body text, on repeated fetch attempts — corroborates the layout in more detail: a ruler sits "above" the waveform and "shows time divisions so you can align regions and make edits at precise time positions"; a playhead "reflects the current playback position"; and a menu bar area contains "menus with region editing commands and functions, as well as buttons for Flex editing, selecting editing tools, and zooming the editor" (logicpro.skydocu.com/en/logic-pro-basics/logic-pro-interface-overview/editors/audio-track-editor/ — flagged secondary/third-party mirror, corroborating but not itself Apple's page). The ruler's time format is switchable — Logic's Tracks-area ruler shows "bars and beats" for musical-grid projects or "minutes and seconds" otherwise, and the Audio File Editor's ruler separately supports samples, minutes/seconds, SMPTE time, or bars/beats (search-indexed summary of Apple's own "Change the ruler display" support articles; the specific Apple URLs — support.apple.com/guide/logicpro/change-the-ruler-display-lgcp2158ca71/mac and the lgcp5df34903 variant — were fetched but returned navigation-only content each time, so this specific claim is included with the caveat that it reflects search-engine indexing of Apple's page rather than a confirmed direct-fetch quote).

**Ableton Live (Ableton):** The Clip View's audio-editing pane is the Sample Editor: "The Sample Editor allows you to view the sample's waveform and control Live's sample-warping capabilities" (ableton.com/en/manual/clip-view/). Loop/playback boundaries are drawn as explicit draggable chrome, not dimming: "the loop region is represented by the loop brace. You can click and drag on the loop start and end markers to change the position and length of the loop brace" (same source). A separate always-visible overview strip, independent of the main zoomed waveform, is built in: the "Clip View Selector... always shows the complete clip, from start to end. The black rectangular outline represents the part of the clip that is currently displayed" (same source) — functionally the same overview-bar idea found in both Fission and Sound Studio above. Scrubbing is a first-class interaction: users can "scrub through the music" directly (same source).

**Why the DAW density is the wrong reference for AppTape:** both tools are built around *many* simultaneous tracks/clips, tempo-grid-relative time (bars/beats, warping), destructive-vs-non-destructive editing decisions per-region, and toolbars full of per-region tools (Flex, warp markers, quantize) that only make sense in a multitrack, tempo-aware context. AppTape edits exactly one Recording, has no tempo grid, and Trim is deliberately non-destructive and non-deletable-until-Export — most of Logic's/Ableton's chrome (region-vs-region operations, per-track effects, warp/Flex UI) has no analogue in AppTape's model at all.

## Synthesis: cross-app patterns

- **A ruler is the norm among trim/edit tools, not the exception.** Fission (rogueamoeba.com/fission/releasenotes.php), Sound Studio (felttip.com/ss/reference.html), Descript (help.descript.com/hc/en-us/articles/10249275208717-Timeline-overview-classic), and Logic (support.apple.com/guide/logicpro/overview-lgcp650a7dcc/mac; logicpro.skydocu.com mirror) all document one. QuickTime — the deliberately bare floor — is the one researched app confirmed to omit it (support.apple.com/guide/quicktime-player/trim-a-movie-or-clip-qtpf2115f6fd/mac). Hindenburg and Amadeus Pro's ruler presence could not be confirmed either way from the sources reached, but neither documents its *absence*.
- **Where meters exist, they cluster at the bottom of the window, separate from the waveform lane itself**, not overlaid on it. Sound Studio puts input/output meters with gain sliders "at the bottom of this window" (felttip.com/ss/reference.html). Piezo's meters sit *above* its (non-existent) waveform area, as the primary content of the window (rogueamoeba.com/support/manuals/piezo/?print=true). Hindenburg exposes meters as a switchable widget (five standards) alongside per-track controls (hindenburg.com/academy/guides/guides-hindenburg-pro/). Audio Hijack is the outlier: it puts live levels in a **list row** (the Session List's Meters column), not in an editing pane at all (weblog.rogueamoeba.com/2023/01/20/level-up-to-audio-hijack-4-1/). Fission, Descript's Timeline (beyond a passing "audio levels" mention in the ruler), and QuickTime show no dedicated meter widget in the sources reached.
- **A second, smaller "overview" waveform strip recurs independently across very different apps** — Sound Studio's Overview pane (felttip.com/ss/reference.html), Fission's "overview bar at the top of a file" (rogueamoeba.com/fission/releasenotes.php), and Ableton's Clip View Selector (ableton.com/en/manual/clip-view/) all do the same job: always show the whole file/clip, with a rectangle marking the currently-zoomed viewport. This pattern appears specifically in apps that support zoom — it's a zoom-navigation aid, not a decorative addition, and it has no reason to exist in a UI (like AppTape's current one) that never zooms.
- **Mirrored, centerline waveform rendering is common but not universal**, and is explicitly a *toggle* in at least one app rather than a fixed choice. Fission mirrors around "the zero dB center line" (rogueamoeba.com/fission/releasenotes.php). Descript's Mirror option is opt-in per waveform style, off by default for some styles, and explicitly produces "a mirrored reflection below" only when enabled (help.descript.com/hc/en-us/articles/10256425252749-Waveforms). Hindenburg's guide points at a non-mirrored, peak-only display mode as an available option (hindenburg.com/academy/guides/guides-hindenburg-pro/), and a claim (unconfirmed by direct fetch here) suggests its default may be a rectified, non-mirrored style. AppTape currently draws a filled/tinted shape, closer to Fission's model than to a bare outline.
- **Per-channel stereo display is real but is handled as separate lanes tied to selection, not just decoration.** Sound Studio lets a user Cmd-click into one channel's lane to select just that channel (felttip.com/ss/reference.html). Amadeus Pro's document model gives stereo sound its own track type with (per an unverified-by-fetch secondary claim) upper/lower channel lanes (man.dsd.net/amadeus/en/basics_document.htm). AppTape's Recordings can be mono or stereo depending on Source, but the current `TrimTimeline` draws one summed lane regardless.
- **The trimmed-away region is depicted three different ways across peers, and none of them match AppTape's translucent-dim overlay exactly.** QuickTime crops the visual scrubber to just the kept range, using handle position rather than dimming (support.apple.com/guide/quicktime-player/trim-a-movie-or-clip-qtpf2115f6fd/mac). Screen Studio marks a trim point with an icon-bubble rather than shading a region at all (screen.studio/guide/trimming). Ableton uses draggable "brace" chrome around a loop/region rather than any fill treatment (ableton.com/en/manual/clip-view/). None of the researched apps were confirmed to use AppTape's specific approach — a translucent color wash over the discarded range while still rendering its waveform — which is notable, since it's the one visual choice in AppTape's current design that directly encodes its "Trim never deletes anything" domain rule (see CONTEXT.md).
- **Timecode is overwhelmingly display-only where documented, with one clear exception.** Sound Studio's readout is a passive "time readout for the current cue position" (felttip.com/ss/reference.html). Descript's ruler "displays" timecode (help.descript.com/hc/en-us/articles/10249275208717-Timeline-overview-classic). QuickTime is the one confirmed case of a genuinely typable numeric field, but it's reached via a menu command ("View > Time Display > Go To Timecode, then enter the timecode you want" — support.apple.com/en-ca/guide/quicktime-player/qtp6cee0761b/mac), not an inline click-to-edit field in the transport row itself.
- **The low-chrome floor and the high-chrome ceiling, with the trim-and-export apps in between:** QuickTime Player's trim UI (support.apple.com/guide/quicktime-player/trim-a-movie-or-clip-qtpf2115f6fd/mac) is the sparsest — no ruler, no meters, a floating and dismissible transport overlay, and modal (not live) trimming. Logic Pro and Ableton Live sit at the opposite end, with rulers, warp/Flex tooling, per-region editing menus, multiple synchronized views, and metering built for a multitrack, tempo-grid context that doesn't apply to AppTape. The trim-and-export peers researched — Fission, Sound Studio, Amadeus Pro, and (with caveats about its transcript/multitrack orientation) Hindenburg — sit clearly in between: each adds at least a ruler and/or an overview strip and/or meters to a single waveform lane, without going anywhere near DAW-level per-region tooling. That middle band — ruler-plus-overview-plus-meters around one waveform, for one file — is the zone AppTape's current, structurally bare detail pane sits below.

## Options for AppTape's empty space

These are raw options, not a recommendation. Each is grounded in a specific cited peer, with a note on fit given AppTape's one-Recording-at-a-time, Trim-never-deletes model.

- **A compact time ruler under (or above) the waveform, seconds/mm:ss-labelled, non-editable.** Grounded in Fission's restored "upper timeline ruler" (rogueamoeba.com/fission/releasenotes.php), Sound Studio's per-pane ruler "in minutes, seconds and fractions of a second" (felttip.com/ss/reference.html), and Logic's Audio Track Editor ruler (support.apple.com/guide/logicpro/overview-lgcp650a7dcc/mac; logicpro.skydocu.com mirror). AppTape already has a `showsRuler` parameter wired into `TrimTimeline` and simply never turns it on — this is close to a "flip it on" option rather than new surface area. Good fit: cheap, additive, doesn't interact with Trim/Seam semantics at all.
- **A small always-visible "overview" strip showing the whole Recording, independent of the main lane, once/if AppTape ever adds zoom.** Grounded in Sound Studio's Overview pane (felttip.com/ss/reference.html), Fission's overview bar (rogueamoeba.com/fission/releasenotes.php), and Ableton's Clip View Selector (ableton.com/en/manual/clip-view/). Fit: currently a poor match — AppTape's waveform always fits the full window width by design (no zoom), so an overview-of-the-viewport strip has nothing to summarize yet. This option is really a *prerequisite-gated* one: it only becomes relevant if zoom is added later, at which point it directly addresses "how do you not get lost while zoomed in," the same problem it solves in every peer that has it.
- **A typable "go to time" entry, reached via a command rather than inline-editable text.** Grounded in QuickTime's "View > Time Display > Go To Timecode, then enter the timecode you want" (support.apple.com/en-ca/guide/quicktime-player/qtp6cee0761b/mac). Fit: modest value for a Recording that's typically short and always fully visible (no zoom to navigate out of); more useful if Recordings can be long, less useful if they're typically short voice clips.
- **Level/loudness metering surfaced somewhere in the editor**, in one of two shapes seen in peers: (a) a small live meter during playback, as in Sound Studio's input/output meters with gain sliders (felttip.com/ss/reference.html) or Piezo's needle VU meters (rogueamoeba.com/support/manuals/piezo/?print=true); or (b) a switchable/loudness-standard meter, as in Hindenburg's five meter types including EBU R128 (hindenburg.com/academy/guides/guides-hindenburg-pro/). Fit: AppTape already has a first-class Loudness domain concept applied at Export time (per CONTEXT.md) but no live meter in the editor — a static loudness readout (this Recording measures X LUFS, will be corrected to Y at Export) would tie an existing domain concept to the empty space without requiring a live VU-style widget; a live needle/bar meter makes less sense post-hoc on an already-captured Recording (there's nothing "live" left to meter) the way it does in Piezo or Sound Studio, which meter *during* capture.
- **A resizable/toggleable meter column living in a list row rather than the editor pane**, per Audio Hijack's Session List Meters column (weblog.rogueamoeba.com/2023/01/20/level-up-to-audio-hijack-4-1/). Fit: this maps more naturally onto AppTape's Library sidebar rows than onto the detail pane the issue is about — worth noting as a "the empty space might not be the only place to put this" option, since the issue's framing is specifically about the detail pane.
- **A visible transcript/word layer above the waveform**, per Descript's script-editor-plus-timeline model (help.descript.com/hc/en-us/articles/37585546799757-The-editor-interface) and Hindenburg's stated "transcript-based workflows" combined with waveform editing (hindenburg.com/products/hindenburg-pro/). Fit: poor near-term fit — this presupposes a transcription pipeline AppTape doesn't have per the grounding material, and both source apps use the transcript as an *editing surface* (delete words to cut audio), which conflicts with Trim's non-destructive, two-handle model; would be a much larger feature than "filling empty space."
- **Region-boundary chrome as icon markers rather than a dimmed overlay**, per Screen Studio's "yellow bubble with a scissors icon" at each trim point (screen.studio/guide/trimming) or QuickTime's crop-to-kept-range handle bar (support.apple.com/guide/quicktime-player/trim-a-movie-or-clip-qtpf2115f6fd/mac). Fit: actively poor for AppTape's specific model — both peer patterns either crop the trimmed-away audio out of view or reduce it to an icon, which reads as "this part is gone," directly contradicting AppTape's domain rule that Trim never deletes anything and the trimmed audio is still there, still playable, still recoverable. AppTape's existing translucent-dim-but-still-rendered treatment is arguably already a better fit for its own semantics than any single peer researched here; if this area changes, the change would need to preserve "still visibly present, just deprioritized," not adopt a peer's crop/icon pattern wholesale.
- **A denser toolbar/menu-bar row above the waveform** (tools, zoom, view options), per Logic's Audio Track Editor "menu bar with local menus, tools, and other controls" (logicpro.skydocu.com mirror of Apple's guide) or Fission's Remove/Crop/Split/Fade/Normalize button row (rogueamoeba.com/support/manuals/fission/?print=true). Fit: mismatched in degree — those buttons exist because their apps support multiple destructive operations (crop, split, join, fade, normalize) that AppTape's model doesn't have (Trim is the only edit operation, and it's non-destructive); adopting the row without the operations behind it would be chrome for its own sake.
